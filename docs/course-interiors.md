# Course interiors: Schedule, Exam, Topics and Resources

## Design brief

Turn each course into a usable study workspace, continuing the resource-first Notes library. Use the existing navy, terracotta and warm-paper tokens, self-hosted typography and meaningful whitespace. Give every section one clear task: plan the next class, verify the assessment, choose a topic, or find a trustworthy resource. Keep both themes, small-screen use, keyboard interaction and existing course URLs intact.

## What changed

- A shared, scoped renderer in `course-workspace.js` and `course-workspace.css` covers all eight courses. Existing overview, lecture, practice and topic-reader implementations remain in place.
- Schedule has Bologna-time upcoming/all/past filters, integrated-course module filtering, an in-progress/next-session card, map and calendar actions, and published teaching-block guidance.
- Exam separates the date feed, assessment record, personal course status and official registration. Its four-item preparation checklist lasts only for the open page. An existing exported calendar is an explicitly labelled fallback, never a live verification or a source of invented start times.
- Topics include the full syllabus, including honest unavailable states. Search, module/progress filters, bounded results, existing bookmarks, self-reported progress and the original readers remain connected.
- Resources pin Virtuale and course-page links above searchable, source-labelled entries. Saved-only filtering uses the existing saved-list format. Missing URLs and example entries are explicitly labelled. Direct links reveal entries beyond the first results page.
- The timetable and exam feed now have independent failure states. Delayed date responses do not destroy a search, practice attempt, reader position or unsaved workshop. All four sections remain navigable during outages.
- Right to Health retains its supplied course notices, reading caveats and dedicated guide reader. Three existing notice renderers are exported for reuse instead of copying or reinterpreting their content.

## Sources, scope and boundaries

Course facts still come from `content/programme.json` and course materials from the existing `content/modules/` files. No new dates, assessment rules, lectures, grades or source verification dates were invented. No professor files were reuploaded. Official materials stay on university platforms. No content JSON/Markdown records, saved IDs, progress keys, account features, tracking or remote storage were added or changed.

A calendar entry is not exam registration. Live-feed exports reuse the existing calendar helper; where that helper estimates an end time or uses a missing-start placeholder, the interface says so. Calendar-copy fallback dates are not exported as confirmed sittings. Local progress is self-report, not proof of exam readiness. Resource host labels indicate the destination, not endorsement or independent fact checking.

## Validation and reproduction

Run `node scripts/stamp-versions.js` after relevant source changes. Then:

```sh
node scripts/check-content.js
node scripts/check-contrast.js
node tests/notes/schedule.test.js
COURSE_SCREENSHOT_DIR=previews/course-interiors node tests/notes/course-interiors.test.js .
npm run test:notes
node tests/notes/workspace.test.js .
npm run test:practice
node tests/right-to-health/content.test.js
```

The focused browser test serves the real site over HTTP under the GitHub Pages subdirectory. It uses explicitly fictional timetable/exam fixtures, a controlled clock and the repository's real public course content. It checks all four sections, all eight courses, missing/partial/delayed feeds, saved IDs, readers, progress, calendar downloads, keyboard navigation, browser history, deep links, Bologna timezone and 32 responsive combinations (320/390/768/1440 pixels, light/dark). Screenshots of Schedule and Exam are **test fixtures**, not a published timetable. Topics and Resources use the existing public course data.

The companion GitHub Actions workflow runs those actual-origin tests and uploads previews. Adapted inline previews from restricted environments are not substitutes for HTTP, storage or offline checks. CI logs are the evidence of which validations passed for a specific commit.

## Maintenance

Keep the four-section layout scoped. Do not duplicate official course facts in this renderer. Resource and topic filters are in-page state; bookmarks and learning progress reuse the existing stores. Do not change those storage keys when extending the UI. `course.html` imports the new files and `sw.js` precaches them; content fingerprints remain generated by the existing stamping script.
